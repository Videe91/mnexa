# MNEXA Implementation Plans

Implementation plans define **how an approved specification will be built**.

Plans should be task-sized, test-first where behavior is involved, and explicit about files, interfaces, verification commands, and commit boundaries. Execute one approved plan task at a time.

A plan is subordinate to its governing spec and ADRs. If implementation evidence requires changing a durable contract, stop and revise the decision/spec rather than silently editing the plan around the conflict.

The first planned implementation plan will cover the MNEXA Lab and benchmark harness, after the v0 technical specification and benchmark contract are approved.
