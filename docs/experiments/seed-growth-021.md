# Seed Growth 021 — Retrieval Handle Separation

## Classification

Exploratory fresh retrieval-handle-separation ablation.

## Question

Can MNEXA improve memory selection inside an already-correct candidate
neighborhood by separating retrieval representation from authoritative
semantic representation?

## Principle

> Retrieval handles locate knowledge. Authoritative support supplies
> meaning.

## Motivation

Seed 018 established exact identity addressing.

Seed 019 established graceful hierarchical addressing.

Seed 020 established conjunctive address refinement.

After Seed 020, exact and system+context addressing can isolate a
single memory. The remaining interference frontier is context-only
activation.

A context-only query may correctly narrow twenty memories to a
five-memory neighborhood while still presenting multiple distractor
memories.

Seed 021 therefore freezes routing and changes only the representation
used to rank memories inside that valid neighborhood.

## Experimental Population

20 fresh memories.

Four interference neighborhoods:

- retry-policy
- lane-routing
- channel-session
- storage-finalization

Five memories per neighborhood.

Every transfer query is context-only.

No query exposes:

- system identity
- code identity
- benchmark family ID.

Conjunctive Seed 020 routing must produce exactly five candidates for
every query.

## Condition A — Full-Memory Retrieval Index

Rank the five candidates using their complete compact semantic memory.

Channels:

- semantic
- lexical
- entity

Fusion:

- Reciprocal Rank Fusion
- RRF K = 60

Top K = 3.

## Condition B — Retrieval-Handle Index

Use the exact same:

- candidates
- semantic channel
- lexical channel
- entity channel
- RRF implementation
- RRF K
- top K

but rank against a retrieval-only projection.

The retrieval index contains:

- normalized retrieval HANDLE text;
- structural META;
- entity/address metadata.

For an unresolved grounded support with no normalized HANDLE, the
retrieval index may contain the exact grounded evidence text as
`UNRESOLVED_GROUNDED_SUPPORT`.

This is not promoted into a normalized claim.

## Critical Separation

The retrieval index is NEVER the authoritative semantic payload.

After ranking, both conditions present the unchanged existing compact
semantic memory generated by Seeds 013-015.

Therefore:

retrieval representation
!=
reasoning representation

## Data Flow

available learned memory
→ Seed 020 conjunctive routing
→ five-memory candidate neighborhood
→ retrieval representation
→ three-channel RRF
→ top-three memory IDs
→ original authoritative compact memory
→ transfer reasoner

## Same-State Noise Control

If Conditions A and B select the same canonical memory-ID set:

- use the same frozen authoritative snapshot;
- execute the transfer reasoner once;
- reuse the exact result for both conditions.

No stochastic model difference may be reported as a retrieval
representation effect.

## Primary Metrics

- target selected into top K;

- retrieval precision;
- retrieval recall;

## Secondary Metrics

- retrieval index words;

- task rescue/harm.

## Controls

Both conditions must have:

- identical learned memory;
- identical evidence;
- identical candidate route;
- identical candidate population;
- identical ranking algorithm;
- identical RRF constant;
- identical top K;
- identical authoritative presentation representation;
- identical transfer query;
- identical context budget;
- identical reasoner.

The handle ranker uses zero model calls.

It receives no:

- benchmark target ID;
- semantic clause;
- semantic grader;
- expected answer;
- canonical atomic units.

## Safety

Expected:

`bundle_unsupported_claims_admitted == 0`

No Seed 021 component may rewrite authoritative evidence.

## Strong Success Pattern

A strong result would be:

full-memory selection recall:
lower

handle-index selection recall:
near 100%

handle target visibility:
near 100%

wrong-memory presentation:
materially lower

task success:
equal or higher

unsupported claims:
0

## Failure Interpretation

If handle indexing lowers target recall, inspect whether the target
knowledge exists only in unresolved grounded fallback and therefore
lacks a useful retrieval handle.

If both representations perform similarly, representation noise is not
the principal remaining issue.

If target selection is correct but downstream wrong-memory
presentation remains high, the next bottleneck is context assembly
rather than retrieval ranking.

## Scientific Boundary

Seed 021 does not prove:

- learned retrieval handles;
- cross-domain retrieval;
- million-memory scale;
- fuzzy entity resolution;
- authorization-aware recall;
- contradiction resolution;
- conventional-RAG superiority.

It tests separation of retrieval representation from authoritative
semantic presentation under a frozen five-memory candidate
neighborhood.

## Burn Rule

The fresh Seed 021 taskset is burned after the first live execution.

Do not tune:

- retrieval handles;
- unresolved-support behavior;
- RRF constant;
- top K;

- graders;
- candidate geometry;

against the first live result and rerun it as fresh evidence.
